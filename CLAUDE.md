# stock-alert — project instructions

## Stack
- **Framework:** ESP-IDF v5.5.x (NOT Arduino, NOT PlatformIO)
- **SDK:** ESP-Matter v1.4.x (Espressif official, code-first)
- **Language:** C++17 (set by `idf_build_set_property(CXX_COMPILE_OPTIONS ...)`)
- **Target chip:** ESP32-S3 only (XIAO ESP32-S3 Sense, 8MB flash, 8MB PSRAM)

## Build workflow

Before committing any firmware change, always:

```bash
source ./scripts/activate.sh
idf.py build               # must succeed with no warnings
```

For UI verification (Matter commissioning, HomeKit behavior), flash to the dev unit:

```bash
idf.py -p /dev/cu.usbmodem2101 flash monitor
```

## Hardware constants (do not hardcode elsewhere)

| Constant         | Value                | Where                     |
| ---------------- | -------------------- | ------------------------- |
| Serial port      | `/dev/cu.usbmodem2101` | dev mac only             |
| I2C SDA          | GPIO 5 (D4)          | `main/stock_sensor.h`     |
| I2C SCL          | GPIO 6 (D5)          | `main/stock_sensor.h`     |
| VL53L1X I2C addr | `0x29`               | sensor driver default     |
| LED (status)     | GPIO 21 (built-in)   | `main/app_main.cpp`       |

## Conventions

- **English everywhere** — comments, identifiers, commit messages, log strings. French only for UI strings exposed to the HomeKit accessory name (TBD).
- **No magic numbers** — every threshold, GPIO, or timeout must be a named constant in a header.
- **Hysteresis is mandatory** — never write `if (distance > threshold)` without a paired "back to OK" check. See `architecture-decisions` in memory.
- **NVS for runtime config** — anything the user might tune (thresholds, sample rate) lives in NVS, not in `#define`.

## Commit style

`type(scope): description` — e.g. `feat(matter): add contact sensor endpoint`.

Scopes used:
- `matter` — anything Matter SDK related (endpoints, clusters, commissioning)
- `sensor` — VL53L1X driver and sampling logic
- `build` — CMake, partitions, sdkconfig, scripts
- `docs` — README, CLAUDE.md, comments

## What NOT to do

- ❌ Do not migrate to Arduino framework "for simplicity" — esp-matter requires ESP-IDF.
- ❌ Do not pin ESP-IDF to a version older than v5.5 — ESP-Matter v1.4 requires it.
- ❌ Do not commit `sdkconfig` (it's machine-generated from `sdkconfig.defaults`).
- ❌ Do not commit Matter device certificates (test certs are auto-generated by the SDK).
